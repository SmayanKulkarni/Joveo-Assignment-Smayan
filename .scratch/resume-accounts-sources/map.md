# Resumes, accounts and more job sources

Label: wayfinder:map
Parent: [Talent Market Scout: HLD](../talent-scout-hld/map.md) (the Infra shell's multi-user phase and the Long-term memory pass that [future scope](../../docs/lld/future-scope.md) deferred, plus new jobs sources)

## Destination

An LLD, `docs/lld/accounts-resume-sources.md`, plus updates to the Gateway, Collection, Runtime and Web UI LLDs where they change, and build tickets in value order in `.scratch/resume-accounts-sources-build/issues/`. Together they must be precise enough to build these four things straight from the docs:

1. A Run that reads a resume a CSM uploads for a Customer and, beside its Market Brief, produces a Customer Recommendation with Postings that match it.
2. Sign in with Google for CSMs, each with many private Customers, every Run filed under one Customer, and a Customer Profile learned from that Customer's earlier Runs that improves their later Runs.
3. Arbeitnow as a new jobs source and Collection tool, with the gateway and tools reshaped to hold it beside Adzuna and USAJOBS.
4. Guardrails on every LLM node, old and new, built from open-source frameworks and open-weight models: for each node, what it checks, where the check lives, and what a Run does when it trips.

When the map is done, nothing is left to decide. Writing the code is the next effort.

## Decisions so far

<!-- one line per closed ticket -->

- [Research: Arbeitnow job board API](issues/01-research-arbeitnow.md): keyless, but every filter runs locally on an hourly snapshot of the whole feed (about 21 pages); only DE, GB, FR, CH and NL, about 7 days deep, with no salary, category or close date; a link back is required, and the non-commercial clause needs asking about.
- [Research: durable storage for accounts and Runs](issues/06-research-durable-storage-for-accounts-and-runs.md): Neon Free Postgres in Oregon (Render's free Postgres expires after 30 days, and Supabase and Turso pause), `langgraph-checkpoint-postgres` 3.2.0 fits the pins, prune finished Runs to stay within 1 GB, the gateway cache stays on local SQLite, and resumes are stored as text.
- [Research: signing in across Vercel and Render](issues/07-research-signing-in-across-vercel-and-render.md): proxy `/api` through a Vercel rewrite so a `__Host-` `SameSite=Lax` cookie works everywhere and `EventSource` needs no CORS (streaming through the rewrite still needs a preview test); the fallback is a `Partitioned` cookie, which works in Chrome, Firefox and Safari 26.2+; no tokens in the SSE URL; keep the `Origin` check; `pwdlib[argon2]` for passwords.
- [Research: reading resume files](issues/08-research-reading-resume-files.md): pypdf in layout mode for PDFs (the only library that kept two columns in order) and the standard library for DOCX; scanned PDFs are refused; the upload is a raw body capped at 2 MB with no `python-multipart` and nothing written to disk; one cheap structured call with no name or contact fields, and the skill grounding check is reused; parse outside the graph, redact contact details, and disable tracing and caching so resumes never reach LangSmith or SQLite.
- [Research: open-source guardrail frameworks](issues/22-research-open-source-guardrail-frameworks.md): no local ML check fits Render's 512 MB (guard models are 500 MB to 3 GB), so only rule-based checks and extra LLM calls are left; LLM Guard is archived and needs torch; Guardrails AI clashes with the `rich>=15` pin; NeMo's `check_async` and LangChain's `RedactionRule` both fit inside `Tiers` with the pins, but NeMo's self-check calls go through its own client, outside the retries and cost tracking.
- [Research: guard models and PII filters](issues/23-research-guard-models-and-pii-filters.md): on real Postings, a Jev `Noul` caught 40 of 40 injected sentences with no false alarms, and added to the existing `relevance` request it costs about $0.003 a Run; Prompt Guard 2 and ProtectAI miss most injections once they sit inside a job advert and flag adverts that quote attack phrases; Llama Guard 4 and Nemotron don't look for injection; gpt-oss-safeguard with a written policy caught 37 of 40 for about $0.04 a Run; only Prompt Guard 2 22M int8 comes near Render's 512 MB (about 453 MB with the app); contact details need only regexes or Presidio's pattern recognizers, since spaCy NER tags skills such as Kafka and Python as people and places, and URL rules must not eat `ASP.NET` or `socket.io`.
- [What Arbeitnow does in the gateway](issues/10-what-arbeitnow-does-in-the-gateway.md): offered beside Adzuna only for DE, GB, FR, CH and NL, never alone, in both Brief and resume Runs; a "Mostly no pay" Caveat past half the Sample; a missing salary never blocks a merge; no call counter, just one lazy walk an hour, and a failed walk is `SourceUnavailable`; the non-commercial use is judged to fit, confirmed by the user because this is a personal project, with a courtesy email; one attribution line names every credited source.
- [One gateway for many sources](issues/11-one-gateway-for-many-sources.md): one `COVERAGE` dict read by both `fetch` and `_bound`; duck-typed clients, no `Protocol`; Arbeitnow unmetered like USAJOBS; the snapshot is one L1 row with the 24-hour TTL behind a module-level lock; Postings with pay win `coalesce`, and a missing salary agrees with any pay; descriptions cut at 4,000 characters; `region` uses Adzuna's country root; filtering is local, mirroring `title_only` and the L2 location rule.
- [Choosing among the search tools](issues/12-choosing-among-many-search-tools.md): `search_arbeitnow` is a third tool offered beside Adzuna on every accepted country, amending the two tickets above; a remote Posting is shown to anyone in every Run, skips the country and location filters, and carries a label and an "Includes remote" Caveat, with only Arbeitnow's flagged, by the user's choice; `_cap` stays shared but leaves room for the extra sources; a failed walk is remembered for the Run; the resume agent reuses the tools unchanged.
- [Research: job source terms for CSM use](issues/27-research-job-source-terms-for-csm-use.md): paid or unpaid, Arbeitnow needs written permission because ticket 10's non-commercial reasoning doesn't survive, Adzuna needs a licence (no public price) for both Matches and Briefs after a 14-day trial limited to testing, with an "Adzuna" label on each advert, and USAJOBS is openly licensed and allowed with conditions; this isn't legal advice, and Adzuna's general terms couldn't be read. Not acted on: the user said on 2026-11-02 that this is a personal project, so licences block nothing.
- [Research: holding Customers' personal data](issues/28-research-holding-customers-personal-data.md): "personal project" doesn't exempt real resumes, so seed fictional Customers until a lawyer confirms; the CSM's organisation is the controller, the CSM records the basis and gives notice, and requests come through them; the LLD must pin ten required features (basis and notice record, delete, export, a 24-month limit from last contact, correction, human review of Matches, no sensitive traits, `zdr: true` with a provider allowlist, nothing in traces or logs, nothing in Briefs); US hosting is allowed under SCCs, but Vercel Hobby doesn't fit real commercial use, Neon's full-disk state blocks deletes, and regions must be chosen before real data; this isn't legal advice. Mostly not acted on: the user said on 2026-11-02 that only test resumes will be used, never real people's, so only three of its features stay.
- [Accounts and sign-in](issues/14-accounts-and-sign-in.md): Sign in with Google only, gated by an `allowed_emails` setting that replaces the access code; a 30-day opaque `__Host-session` cookie through the Vercel rewrite; `csms` and `sessions` in Neon with no Alembic; every `/api` read now needs a session except `/api/meta` and sign-in; the CLI and local `scout web` stay login-free when `database_url` is unset.
- [What a Resume is for](issues/17-what-a-resume-is-for.md): one kind of Run with two deliverables, a Market Brief about the market and a Customer Recommendation about the person (title, salary and skills to aim for, plus ranked Matches when there's a Resume); the Resume drafts the Hiring Request and Clarifying Questions stay; one current Resume per Customer, separate from the Customer Profile.

- [Matching Postings to a Resume](issues/18-matching-postings-to-a-resume.md): computed with no LLM, over the Sample only, in one `match` node after `stats`; the score is the weighted share of the Posting's skills on the Resume, with a separate Level, and a failure can't lose the Brief.
- [Customers and what a CSM can do with them](issues/26-customers-and-what-a-csm-can-do-with-them.md): a name and an optional note, created by hand; a hard delete reaches everything except LangSmith, and another CSM's Customer gets 404.
- [Runs that belong to a Customer](issues/15-runs-that-belong-to-a-customer.md): `customer_id` in the `runs` registry, checked in the API layer with 404; no moving, but a Run can be deleted; seeds are local only, and the global Adzuna guard stays the only quota.
- [What a Customer Profile holds](issues/16-what-a-customer-profile-holds.md): typed defaults computed by code from the last 10 Done Runs, in a plain table, not the Store; the CSM can set, remove and clear values, and a Run can opt out.
- [How a Customer Profile shapes a Run](issues/19-how-a-customer-profile-shapes-a-run.md): it fills only null request fields as Assumptions, gives `plan` title hints, and adds one comparison line to the Customer Recommendation.
- [Resume, profile and sign-in screens](issues/20-resume-profile-and-sign-in-screens.md): decided in words with no prototype; Runs start only from inside a Customer, a finished Run has two tabs, and Matches are passed on by download.
- [Guardrails for the existing LLM nodes](issues/24-guardrails-for-the-existing-llm-nodes.md): one Jev Noul in `relevance` drops Postings that address an AI, plus a skill name length rule and a link scheme rule; no framework. Jev's openness wasn't confirmed against the destination's wording.
- [Guardrails for the resume and profile nodes](issues/25-guardrails-for-the-resume-and-profile-nodes.md): resume parse gets redaction, a narrow schema and grounding; matching and the profile use no LLM, so they need no model rail.

## Out of scope

- Writing the code. That is the build effort after this map.
- Passwords, any sign-in provider other than Google, and two-factor auth. A CSM signs in with Google only, by the user's choice on 2026-11-02.
- Roles beyond "a CSM sees only their own Customers": admins, teams, organisations, sharing Customers or Runs between CSMs, and a button to hand a Customer to another CSM.
- Customers signing in, uploading their own resume, or receiving anything from the system directly. The CSM passes results on.
- Applying to jobs, writing cover letters, or rewriting the resume for the user.
- Scraping job sites ourselves. Only APIs.
- Billing, or paid plans for users.
- Every RapidAPI job source. The user dropped them on 2026-11-02 and kept only Arbeitnow.
- [Remote Postings on Adzuna and USAJOBS](issues/12-choosing-among-many-search-tools.md). The user chose to skip them on 2026-11-02, so only Arbeitnow's reach people in other countries.
- Handling real people's data: consent records, export, automatic deletion, private LLM routing, regions and paid hosting from [Research: holding Customers' personal data](issues/28-research-holding-customers-personal-data.md). The system only ever holds test resumes, by the user's choice on 2026-11-02. Using real resumes would mean redrawing the destination.
- Hosted vendor guardrails: AWS Bedrock Guardrails, Azure AI Content Safety, Lakera and the like. The user asked for open-source frameworks. Open-weight guard models served by OpenRouter are still in.
