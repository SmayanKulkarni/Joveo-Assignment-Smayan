## Question

How should the new screens look and behave inside the existing web UI shell (sidebar, Run column, trace panel, neumorphic look)?

- The Customer list: finding, adding and opening a Customer, and how the current Customer stays obvious so a CSM never files a Run under the wrong person.
- Sign in with Google and log out, and what a signed-out visitor sees.
- Resume upload: the drop zone, parse progress, the parsed facts for the CSM to correct, with additions marked "added by CSM", and starting a Run from them.
- The Customer Recommendation beside the Brief: the title, salary and skills to aim for, then the Matches with rank, score, matched and missing skills, a link to the Posting, and its source's attribution.
- The profile page: what was learned, from which Runs, and edit and clear controls.
- How a CSM passes Matches on to the Customer, if the screen needs anything for it.
- How a Run shows its two deliverables, and how the Run Notes show what the profile changed.

Build it with the `prototype` skill as a throwaway in `../assets/`, with fixtures and no backend, and link it from the Answer.
